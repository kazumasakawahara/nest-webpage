# Orca 練習メニュー ―「道具箱で、あそぶ」を題材に（2026-08-25）

河原さんの希望：連載「道具箱で、あそぶ」（issue #8〜#10）の制作を、Orca（Agent IDE）の練習題材にもする。

## Orca のおさらい（要点だけ）

- タスクを作るたびに**本物の git worktree** が1つ切られ、その中で好きな CLI エージェント（Claude Code 等）が走る。作業が物理的に別フォルダに分かれるので混ざらない
- 標準ワークフローは**ファンアウトと比較**：同じ指示を複数エージェントに振り、差分を並べて勝ちをマージ
- 人間の仕事は「書く」より「**差分を読んで選ぶ・差し戻す**」。AIの差分にMarkdownでコメントを付けて突き返す機能がある
- Orca 本体は無料（MIT）。課金は差し込んだエージェント側（並走させた本数ぶん増える）
- 導入（未導入の場合）: `brew install --cask stablyai/orca/orca`。Claude Code の認証が済んでいれば差すだけ

## なぜこの3 issueが練習題材に向くか

- **#8（特集枠組み）**：小さく、完了条件が機械的（build成功・一覧に描画）。「1タスク＝1worktree」の基本動作を一周するのにちょうどよい
- **挿絵・キャッチコピー**：正解が一意でない仕事は「複数案を並べて選ぶ」Orcaの型と相性が最良
- **#9→#10（記事2本）**：#10は#9の素材に依存する**直列**の関係。「並列にしてよい仕事と悪い仕事の見極め」まで練習できる

## 練習メニュー（易→難の4段階）

### 練習1：単走で一周する（題材：#8）

1. Orca でこのリポジトリを開き、新規タスクを作成（worktree が切られる）
2. エージェント（Claude Code）に issue を渡す。指示文は短くてよい：「issue #8 を読んで実装して。push はしないで」
3. 完了したら **diff を全部読む** → worktree のターミナルで `npm run build` と `npx vitest run` を自分で叩いて確認
4. 納得したらマージ。これで「タスク作成→実行→検証→マージ」の基本が一周

### 練習2：ファンアウトで勝ちを選ぶ（題材：#8の挿絵とキャッチ）

1. 同じ指示（「特集『道具箱で、あそぶ』の挿絵SVGとキャッチコピーを作って。一覧ページに組み込むところまで」）を**2〜3タスクに振って並走**させる
2. 始める前に**勝ちの評価軸を一文**で決めておく（例：「既存3特集の挿絵と並べたとき、浮かないこと」）。これがOrca運用のコツ
3. 差分とプレビューを見比べて1つ選び、勝ちだけマージ。負けのworktreeは捨てる
4. 注意：並走させた本数ぶんClaude側の消費も増える。比較は2〜3本まで

### 練習3：レビューの往復（題材：#9の記事本文）

1. 1タスクで #9 の記事本文を書かせる
2. 出てきた差分に **Markdownコメントを付けて差し戻す**練習（例：「この段落は表記方針と違う」「挿絵は人形劇様式ではなく実画面スクショ」）。修正→再コミットまでエージェントにやらせる
3. これが身につくと「書き直しを口頭で全部説明する」より速くなる

### 練習4：並列の見極め（題材：#10）

- #10（ラジオ局）は #9 の素材を使うので、**#9 と並列にしない**（マージ衝突と手戻りのもと）
- 並列にしてよいのは独立した仕事だけ。#9 の執筆中に並走させるなら、例えば「ポケットにスキット追加」「既存記事の誤字直し」のような**触るファイルが重ならない**タスク

## この作業部屋（Discord連携）との交通整理

- この部屋も同じリポジトリの worktree で動くため、**同じ issue を二重に進めると衝突**する
- 運用ルール案：Orca練習でやる issue は、着手前にこの部屋へ「#8はOrcaでやる」と一言もらう。その issue には私は触らず、質問・レビュー相手に回る
- 逆に「途中まで練習→残りはお任せ」も可。その場合はブランチ名を教えてもらえれば続きから引き継ぐ

## 注意（nest-webpage 固有）

- **main への push ＝ 即公開**（Cloudflare 自動デプロイ）。練習中のエージェントには毎回「push はしないで」を付け、公開判断は必ず河原さんの手で
- #9・#10 の**実画面スクショ工程は Orca 練習に向かない**（河原さんの Chrome を対話的に使うため）。記事本文・コード・SVG までを練習範囲とし、スクショはこれまで通りの共同作業で
- 記事の文責は最後に人が読んで担保（AIの下書き→河原さんの目、はいつも通り）
