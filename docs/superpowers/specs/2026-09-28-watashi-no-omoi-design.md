# 「私の想い」コーナー 設計書

- 作成日: 2026-09-28
- 状態: 設計確定（河原さん承認済み）→ 実装計画待ち
- 対象ページ: `/post-parent/`（親なき後）

## 1. 目的

「親なき後」について、家族が抱えている想いを寄せてもらい、サイトに掲載する。

- **第一の目的：共感の場。** 同じ立場の家族が読んで「自分だけじゃない」と感じられること。
- **ページ作りへの参加。** 家族に書き手としてページ作りに加わってもらうこと。投稿の件数が少なくても、この目的は損なわれない。
- **第二の目的：声を集める。** 集まった想いを、勉強会・資料作り・提言など nest の活動に生かすこと。

共感の場と声を集めることがぶつかるときは、共感の場を優先する。

## 2. 決定事項

| 項目 | 決定 | 理由 |
|---|---|---|
| 投稿できる人 | 家族全般（親・きょうだい・祖父母・その他の家族） | 「親なき後」はきょうだいにも切実。ご本人・支援者は場の性格がぶれるため対象外（将来の別コーナー候補） |
| 掲載名 | ペンネームか「匿名」のみ。実名は受け付けない | 親の実名からお子さんが辿れてしまう。お子さん本人は掲載に同意していない |
| 受付の仕組み | Google フォーム＋Apps Script＋スプレッドシート | 「教えてAIさん」質問箱（`scripts/create-ai-tips-question-form.gs`）で実績あり。サーバー不要 |
| 審査 | 一次確認は担当者、最終判断は河原さん | 悩みの深い投稿は判断が揺れるため二人の目を通す。責任者は一人に固定 |
| 掲載の仕組み | 静的サイト（Markdown を1投稿1ファイル） | 公開文はすべて Git に記録が残り、取り下げはファイル削除だけで済む |
| 即時公開 | しない | 意図せず個人が特定される情報が入っている危険が最大のリスク |
| 特定の相手への不満・批判 | 掲載しない（nest 自身・他の事業所・行政・個人のいずれも） | 「私だけじゃない」と感じてもらう場の趣旨から外れる。投稿そのものは受け止め、活動の見直しに生かす（§6.1） |

## 3. 全体の流れ

```
[家族] ─投稿→ [Google フォーム]
                 │ 送信トリガー（Apps Script）
                 ├→ 通知メール（担当者・河原さん）
                 ├→ 受付確認メール（メール記入者のみ）
                 └→ スプレッドシートに1行（状態＝未確認）
                         │
             [担当者] 一次確認：チェックリスト＋「掲載用本文」列を作成
                         │
             [河原さん] 最終判断：掲載可／要本人確認／見送り
                         │ 掲載可のみ
             「掲載用本文」だけを Markdown 化 → src/content/post-parent-omoi/
                         │
                     通常のデプロイ（main push）で公開
```

**原文を読むのは、スプレッドシート上の人（担当者・河原さん）だけ。** この作業部屋（Claude を含む）には、個人に結びつく情報を持ち込まない決まりがあるため、Claude が受け取るのは「掲載用本文」列など、個人が特定される部分を伏せ終えた文章に限る。原文を Claude に一次チェックさせる運用はしない。

## 4. 受付フォーム

### 4.1 項目

| # | 項目 | 形式 | 必須 | 備考 |
|---|---|---|---|---|
| 1 | お題 | 選択 | ○ | §4.3。「自由に」を含む |
| 2 | 想い | 段落 | ○ | 目安は 400〜800 字。上限の目安は 1,200 字（入力規則は付けず、説明文で伝える） |
| 3 | お立場 | 選択 | ○ | 親／きょうだい／祖父母／その他の家族 |
| 4 | 年代 | 選択 | — | 20代以下〜80代以上／答えない |
| 5 | 掲載名 | 記述 | ○ | ペンネーム。空欄にしたい場合は「匿名」と書くよう案内 |
| 6 | 掲載の希望 | 選択 | ○ | 「掲載を希望する」／「掲載は希望せず、nest に届けるだけ」 |
| 7 | 掲載への同意 | チェック | 6 で掲載を希望した場合は必須 | 掲載することと、編集部が個人の特定につながる部分を伏せたり言い換えたりすることへの同意 |
| 8 | 活動への活用 | チェック | — | 掲載とは別に聞く。「掲載されない場合も含め、個人が特定されない形で nest の活動（勉強会・資料作りなど）に生かしてよい」 |
| 9 | 連絡先メール | 記述 | — | 非公開。記入がある場合は、修正後の文章を掲載前に確認してもらう。受付確認メールもこの宛先に送る |

Google フォームは条件付きで必須にできないため、7 は「必須チェック＋『届けるだけを選んだ方もチェックしてください』」とするか、セクション分岐で 6 の答えに応じて 7 を出すかのどちらかにする。どちらにするかは実装計画で決める（セクション分岐を第一候補とする）。

### 4.2 フォーム冒頭の注意書き（要旨）

- ここに寄せられた想いは、編集部が読んでから掲載します。すぐには載りません。
- **実名、お子さんのお名前、学校名・施設名・事業所名、お住まいの地域は書かないでください。** 書かれていた場合は、編集部が伏せたり言い換えたりします。
- まとまっていない文章や、答えの出ていない迷いも歓迎します。
- 特定の事業所・機関・個人への不満やご意見は、このコーナーには掲載しません。お問い合わせフォームで個別にお受けします。
- 掲載後に取り下げたいときは、お問い合わせフォームからご連絡ください。

### 4.3 お題（初期）

気持ちを書き出しやすい問いを中心にする（共感の場を優先するため）。

1. 子どもに遺したい言葉
2. いま一番気がかりなこと
3. こうなっていたら安心できる
4. 自由に

提言向けのお題（例：「行政に望むこと」）は、運用が落ち着いてから追加を検討する。

## 5. スプレッドシート（審査台帳）

フォームの回答列に、編集部の管理列を追加する（質問箱の `addEditorialColumns_` と同じ方式）。

| 管理列 | 入力者 | 内容 |
|---|---|---|
| 状態 | 自動→担当者→河原さん | 未確認 → 一次確認済 → 掲載可／要本人確認／見送り → 掲載済／取り下げ |
| 一次確認者 | 担当者 | 名前 |
| 一次確認メモ | 担当者 | チェックリストで気づいた点 |
| 掲載用本文 | 担当者 | 伏せ字・言い換えを済ませた本文。**Claude に渡すのはこの列だけ** |
| 最終判断メモ | 河原さん | 判断理由（見送り理由を含む） |
| 掲載日 | 掲載作業者 | 公開した日 |
| 掲載ファイル名 | 掲載作業者 | `src/content/post-parent-omoi/` 内のファイル名。取り下げ時に使う |

通知先（Apps Script の宛先定数）は、担当者と河原さんの2名。具体的なアドレスは実装時に河原さんに確認する（既存スクリプトの `NOTIFY_EMAIL` は 1 宛先なので、複数宛先に対応させる）。

## 6. 一次確認チェックリスト（担当者向け、1枚もの）

別紙として作成する（`docs/operations/` 配下を想定）。最低限の項目は次のとおり。

- 人名（本人・家族・支援者・医師など）
- 学校・施設・事業所・病院の名前
- 地域（市区町村より細かいもの。市名も内容次第で伏せる）
- 年齢・学年・診断名・障害の程度などの**組み合わせ**で特定できてしまわないか
- **身近な人（同じ事業所の家族・支援者）が読んで、誰のことか分かってしまわないか。** 見知らぬ読者には分からなくても、狭い地域では分かることがある。エピソードの細部を一般化するか、判断に迷えば「要本人確認」へ
- 特定の相手（nest 自身・他の事業所・行政・個人）への不満・批判になっていないか（→ §6.1）
- 命に関わる危機や虐待の兆候がないか（→ 掲載判断の前に、河原さんへ直ちに相談）
- 連絡先メールの記入があり、伏せ字・言い換えをした場合 →「要本人確認」を提案

### 6.1 不満・批判を含む投稿の扱い

- 投稿全体が特定の相手への不満・批判である場合：**掲載しない**（状態は「見送り」、最終判断メモに理由）。内容は河原さんが受け止め、nest 自身に関するものは活動の見直しに生かす
- 想いの一部に不満・批判が含まれる場合：その部分を除いても想いとして成り立つなら、除いた「掲載用本文」を作り、「要本人確認」とする（連絡先がなければ見送り）。成り立たなければ見送り
- 連絡先メールがある場合は、見送ったことと、お問い合わせ窓口で個別に受け止められることを伝える
- フォーム冒頭の注意書き（§4.2）にも、この方針を一文で示す

## 7. サイト側の構成

### 7.1 コンテンツの置き場所

- `src/content/post-parent-omoi/` に 1 投稿 1 ファイル（Markdown）で置く
- **`src/content/post-parent/` の下には置かない。** 既存のコラムコレクション（`postParentColumn`）が `src/content/post-parent` 配下の `**/*.md` をすべて読み込むため、投稿がコラムとして混ざってしまう
- ファイル名：`YYYY-MM-DD-NN.md`（掲載日＋連番。内容をファイル名に含めない）

### 7.2 frontmatter（案）

| キー | 型 | 例 |
|---|---|---|
| `theme` | お題（列挙） | `nokositai-kotoba` / `kigakari` / `anshin` / `jiyu` |
| `relation` | お立場（列挙） | `oya` / `kyodai` / `sofubo` / `sonota` |
| `ageRange` | 任意の文字列 | `50代` |
| `penName` | 文字列 | `匿名` |
| `publishedAt` | 日付 | `2026-10-05` |
| `draft` | 真偽 | 既定 false |

`content.config.ts` に `postParentOmoi` コレクションとしてスキーマを定義し、列挙外の値はビルドエラーにする。

### 7.3 `/post-parent/` 本体への追加

- 「ゆるく、つながる」セクションの直前に「私の想い」セクションを追加する
- 内容：短い導入文／最新 2〜3 件の抜粋カード（お立場・年代・掲載名・お題）／「想いを寄せる」ボタン（Google フォームへ）／「ほかの想いを読む」（一覧へ）
- 掲載 0 件のときは、抜粋カードを出さず、導入文とボタンだけを表示する

### 7.4 一覧ページ `/post-parent/omoi/`

- カード形式で全文を表示する（短文が中心なので、個別ページは作らない）
- お題ごとに絞り込むボタンを置く（静的ページ内での表示切り替え。JavaScript が無くても全件は読める）
- ページ末尾に「想いを寄せる」ボタンと、取り下げの窓口（お問い合わせ）への案内を置く
- パンくず：親なき後 › 私の想い

### 7.5 デザイン

既存のデザイン方針（温かいエディトリアル、Shippori Mincho、nest 緑＋クリーム＋テラコッタ）に合わせる。カードは手紙や便箋を思わせる落ち着いた見た目にし、SNS のタイムラインのような見た目は避ける。

## 8. 入れないもの

- コメント欄・「いいね」などの反応機能（荒れる心配と管理の手間）
- 即時公開
- 写真の添付（写り込みで個人が特定されるおそれ）
- 実名での掲載
- ご本人・支援者からの投稿（別コーナーの候補として保留）

## 9. 付随作業

1. **プライバシーポリシー（`src/pages/privacy.astro`）に追記：** 投稿の扱い、編集部による伏せ字・言い換え、活動への活用（同意した場合のみ）、連絡先メールの利用範囲、取り下げの窓口
2. **最初の 2〜3 件：** 公開時点で空にならないよう、関係者に書いてもらう（通常と同じフォーム・審査を通す）
3. **一次確認チェックリスト**（§6）を作成して担当者に渡す
4. **フォーム作成スクリプト：** `scripts/create-watashi-no-omoi-form.gs`（質問箱のスクリプトをもとにする）。フォームの作成・トリガー設定は河原さんが Google アカウント上で実行する

## 10. 取り下げ

- 窓口：お問い合わせフォーム（投稿時の掲載名とおおよその掲載日を書いてもらう）
- 手順：台帳の「掲載ファイル名」から該当ファイルを削除 → デプロイ → 台帳の状態を「取り下げ」に
- 本人確認ができない依頼でも、取り下げは受け付ける（載せ続けるより、外すほうが安全なため）

## 11. 検証（実装時）

- `npm run build` が通る（frontmatter の列挙外の値がビルドエラーになることも確認）
- 既存のテスト（vitest）がすべて通る。コレクションの読み込みと 0 件時の表示にはテストを追加する
- 投稿がコラム一覧・トップの新着などに混ざっていないことを dist で確認
- `/post-parent/` と `/post-parent/omoi/` を 375px / 1280px で撮影して目視（横スクロールなし、見出しの折り返し）
- フォーム：テスト投稿で、通知メール 2 宛先・受付確認メール・台帳の「未確認」初期化を確認（河原さんの環境で実施）
