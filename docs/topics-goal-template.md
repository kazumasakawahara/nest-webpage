# トピック記事の推敲に /goal を使うときの条件文（雛形・v1 2026-10-14）

前提：週次の定期タスクが作った PR（ブランチ `claude/topics-watch-YYYY-MM-DD`）を Mac で checkout し、Claude Code で張る。
河原さんが「類型」「合格ライン」「停止条件」を確認してから張る（goal-condition スキル 手順 2・5）。
評価役は会話に出た出力しか見ないので、確かめ方の出力をそのまま会話に出すこと。

## 実行前の確認
- [ ] `git fetch` のあと PR のブランチにいる（`git branch --show-current`）
- [ ] 類型 N を決めた（PR 本文の「類型」を河原さんが確認。違えばここで直す）
- [ ] `node scripts/topic-lint.mjs <記事> --type N` が動く（Mac では `--no-fetch` を付けず URL も確かめる）
- [ ] auto mode（無人で回すとき）

## 条件文（`/goal ` の後ろに貼る。<…> を埋める）

```
src/content/topics/<記事ファイル> を docs/topics-editorial-policy.md の編集方針に沿って推敲する（類型 <N>）。
完了条件: (1) node scripts/topic-lint.mjs src/content/topics/<記事ファイル> --type <N> を実行し、その出力の末尾に「違反 0 件」と表示されている
          (2) Agent ツールで、書き手と別の general-purpose エージェントに scripts/topic-review-prompt.md の依頼文・docs/topics-editorial-policy.md・記事の全文（cat -n）・類型 <N> だけを渡して採点させ、その出力の最終行に「REVIEW_RESULT: … pass=yes」が表示されている（総合 80 以上・最低点 70 以上・重大 0 件）
          (3) npm run build が終了コード 0 で終わり、その出力が表示されている
制約: 記事ファイルと タスク.md・作業ログ.md 以外のファイルを変更しない。法令名・法令番号・条番号・日付・金額・人数・出典 URL は変更しない（文章の推敲のみ）。「（未確認）」の記述を削って解消しない（確認できていないものは残す）。scripts/ と docs/ の検査基準・採点プロンプトを書き換えない。frontmatter の draft: true を外さない。編集者役に書き手の意図や前回の採点を渡さない。push・マージ・デプロイはしない。
進め方: 最初に現状の lint と編集者役の採点を実行して結果を示す。重大 → lint の違反 → 中 の順に直す。各ターンの終わりに完了条件 (1)(2)(3) ごとの現状（達成/未達と根拠の出力）を一覧で示す。
停止: 12 ターンで完了しなければ、または編集者役の総合点が 2 回続けて下がったら、または同じ lint 違反が 3 回続いたら、または指摘を直すのに事実関係の追加調査や法令の解釈が必要と判明したら（推敲の範囲を超える）、未達の条件と理由と残った指摘を報告して止まる。
終了: 完了条件をすべて満たした時点、または停止に当たったことを報告した時点で、この目標は終了とする。
```

## /goal に入れない項目（河原さんの検品）
- 法的な正確さ（条文の読み、当てはめ、施行日・経過措置の理解）
- 言い回しの品位、読者への誠実さ
- 取り上げる価値、公開の可否（`draft: true` を外す判断）
- 「（未確認）」として残った点の確認

## 達成の後
- `git diff --stat` で、記事と タスク.md・作業ログ.md 以外に差分がないことを機械的に確かめる（制約は作業者の自己申告でしか評価役に見えない）
- 公開前は acceptance-inspector で独立に検品する（agent-sop）

## 途中で判断を変えるとき
評価役は条件文しか見ない。合格ラインや類型を変えるときは `/goal clear` → 条件文を直して張り直す。
