くわしい手順書 ④　黒い画面をこわがらない（動作確認の検査を動かす）

日記からつくる、わが子のバイブル（oya-iru-wiki）／ くわしい手順書 全5冊の4冊目

この手順書は、「ターミナル」「コマンド」という言葉に身構えてしまう方のためのものです。 使うのは導入のときのほんの数回、やることはコピーして、貼り付けて、Enter を押すだけです。タイプミスの心配はいりません——全部コピペで進みます。

所要時間: 10分 ／ 前の手順: ③ Claude を用意して、フォルダを見せる ／ 次の手順: なし（これで導入完了。あとは今夜、1行話すだけ）

連絡帳をスマホで撮っている方は、このあと ⑤ スマホの写真を、受付箱に入れる へ進んでください。撮ったその場で受付箱に届くようになります。

そもそも何のために「黒い画面」を使うのですか？

この仕組みには、実名の混入や記録の壊れを機械的に見つける検査（lint）が入っています。人の注意力に頼らないための安全装置です。この検査を一度動かして「違反なし」を確かめるのが、導入の仕上げです。ふだんの検査は AI が自動でやるので、ご自身で黒い画面を使うのは、基本的に今日だけです。

1. 黒い画面を開く

  • Mac: command + スペース を押して「ターミナル」と入力し、Enter。白い（または黒い）文字だけの窓が開きます
  • Windows: スタートボタンを右クリック → 「ターミナル」（または「Windows PowerShell」）を選びます

名前が「ターミナル」でも「PowerShell」でも「コマンドプロンプト」でも、役割は同じです（パソコンによって呼び名が違うだけ）。こわい見た目ですが、ここは「パソコンに文字で指示を出す窓口」です。指示した以外のことは起きません。

2. Vault の場所へ移動する

次の1行をコピーして、黒い画面に貼り付けて、Enter を押します。

  • Mac の場合:
cd ~/Obsidian/oya-iru-wiki
  • Windows の場合:
cd $HOME\Obsidian\oya-iru-wiki

何も起きないように見えたら、それが成功です（移動しただけなので、表示は出ません）。

テンプレートを別の場所に置いた方は、Obsidian/oya-iru-wiki の部分を実際の場所に置き換えてください。分からなければ、フォルダを黒い画面にドラッグ＆ドロップすると場所の文字が入ります（cd と1文字空けてからドロップ）。

3. 検査を動かす

続けて、次の1行を貼り付けて Enter。

python3 scripts/okf_lint.py

「違反なし。」という日本語が出れば合格です。骨格は健全で、追加のインストールも要りません。

Windows で「python3 が見つかりません」と出たら: Microsoft Store が自動で開くか、「ストアから入手」と案内されます。「Python 3」を入れて（無料）、もう一度上の1行を実行してください。

4. ZIP で入れた方だけ — 実行の許可を戻す（Mac のみ・1回だけ）

ZIP でダウンロードすると、検査の仕組みの「実行の許可」が外れていることがあります。次の1行を貼り付けて Enter（手順書①で ZIP を使った Mac の方だけ。Git でクローンした方・Windows の方は不要です）。

chmod 755 githooks/pre-commit scripts/*.py

表示が何も出なければ成功です。

なぜ必要？ — 許可が外れたままだと、危ない保存操作を止める「関所」が黙って効かなくなります。効いていないことは画面に出ないので、ここで一度だけ戻しておきます。

5. （Git を使う方だけ）関所を有効にする

手順書①で「方法B: Git でクローン」を選んだ方は、続けて次も実行します。

git config core.hooksPath githooks

ZIP で入れて Git を使わない方は、この行は飛ばしてください（代わりに「フォルダを公開の場所・共有リンクに置かない」ことだけ守ってください）。

6. おつかれさまでした

黒い画面はもう閉じて大丈夫です（Mac: command + Q／Windows: 窓を閉じる）。

導入は完了です。今夜、Claude にこう話しかけてください。

「今日こんなことがあった。……」

1行でかまいません。それが、わが子のバイブルの1ページ目になります。
